# Changelog

Versions are git tags (`vX.Y.Z`). The iOS build number counts up across versions and is set per
upload through `BODYORACLE_BUILD_NUMBER` (see `Tools/testflight.py`).

## 0.3.0

iOS builds 5 (TestFlight), 6 and 7 (App Store review). Requires Unity 6000.3.24f1, HoloKit Unity SDK `0.6.0-preview.1` (`5a16342`), AR Foundation / ARKit 6.4.3.

### Added

- Hold a pose for one second to hear its character, no button needed (`PoseHold`); holding three
  more seconds repeats it. Space and the Pronounce button still work.
- KTV-style highlight that sweeps across the pronunciation while it is spoken (`KaraokeWipe`,
  timings in `Resources/PronunciationTiming.json`, generated by `Tools/pronunciation_timing.py`).
- iOS: a guide grid and prompt drawn in 3D on the characters' plane, so both eyes fuse them in
  Stereo; the pronunciation sits above the grid in every mode.
- iOS Stereo: parallax correction for the rear camera's offset from the eyes
  (`SpriteVisualizer.stereoSubjectDistance`).
- macOS: zero-copy AVFoundation → Metal camera capture and a View → Enter Full Screen menu, via the
  native plug-in `Assets/Plugins/macOS/BodyOracleMac.bundle` (source in `Tools/macos-native/`).
  `-bodyOracleWebCamTexture` falls back to `WebCamTexture`.
- macOS: full-window camera view, guide grid, and **D** to outline the area the model recognises.
- `Tools/testflight_mac.py` and `BodyOracleBuild.MacRelease` for Mac App Store TestFlight builds.
- Device test flags: `--stereo` and `--plane-distance` in `Tools/test-ios-device.py`; the device
  report records the AR camera pose mismatch and the render mode.

### Changed

- HoloKit Unity SDK `0.5.6` (`ab9560e`) → `0.6.0-preview.1` (`5a16342`), pinned by tag: stereo bar, alignment
  guide, thermal frame-rate caps, low-latency tracking, iOS 27 camera compatibility. AR Foundation
  and ARKit 6.3.5 → 6.4.3.
- Live inference is limited to 5 per second (`Yolo.maxInferenceRate`); video replay is not limited.
  Characters ease between results every rendered frame (`displaySmoothingTime` 0.2 s).
- One character at a time by default (`showSingleCharacter`): the most confident person, which is
  also the one pronounced.
- The model sees the centre 56 % of the camera frame on iOS (`Yolo.cropScale`), with the projection
  plane at 1 m.
- iOS Mono turns the camera image to the current screen orientation before inference.
- Stereo never enters sleep mode; sleep after 30 s without movement now applies to Mono only.
- Tracks show after 2 hits and survive 3 misses (were 3 and 5), matching the lower inference rate.
- Mobile URP asset: HDR and shadows off.
- Stereo keeps Body Oracle's own buttons (Pronounce, Start Recording, Mono), as EchoVision does: the
  SDK 0.6 stereo bar is off (`HoloKitCameraManager.StereoBarItems = None`).
- Stereo renders at 60 fps (`m_StereoFrameRate`), not the display's 120 Hz; the SDK still drops to
  40 / 30 fps when the phone is hot. Unity's own thermal FPS cap is off, as the SDK requires.
- `Tools/testflight.py` exports a signed ipa locally before uploading, and accepts an App Store
  Connect API key (`--api-key-id`, `--api-issuer`) or a manual App Store profile.
- The app moved into the embedded package `Packages/org.realitydeslab.body-oracle` (Runtime,
  Editor, Tests with assembly definitions; scenes, model, sprites, audio, shaders, macOS plug-in),
  laid out like EchoVision's. `Assets/` keeps only project settings.
- No Unity splash screen.
- Build 6: clearer microphone purpose string, and the Info.plist declares no non-exempt encryption
  (`ITSAppUsesNonExemptEncryption = false`), so uploads no longer stop at export compliance.
- Build 7: Unity hardware statistics are off (`submitAnalytics: 0`), so the app sends nothing to
  Unity and makes no network requests at all.
- The app is named **Body Oracle** on the Home Screen and in the Mac menu bar (was `body-oracle`).
- Mono: the guide grid, its prompt and the pronunciation shrink together to fit the screen, so
  the prompt below the grid is no longer cut off in landscape. Stereo keeps the full size.
